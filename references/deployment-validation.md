# 发布与验证

## 确定实际交付路径

读取项目既有部署文档、CI/CD 配置和当前授权，确认受影响组件、环境、精确候选 SHA/镜像、配置和数据变更、执行顺序、健康检查与回滚点。发现已有自动部署链路时沿用，避免重复执行。

工作台本身通过 `workspace serve` 在本机启动，不代表业务应用已部署。安装 skill 也不配置开机启动、远端服务或定时自动运行 agent。

## 执行与留痕

- 优先使用环境中已有的官方 API、CLI 或连接器。无可用适配器时给出具体缺口和人工步骤，继续不依赖该平台的工作。
- 按用户已有授权执行；新的生产目标、数据库迁移或不可逆动作需要适用的授权。执行前准备好具体组件、版本、目标、顺序与回滚，使确认只发生在必要边界。
- 记录发布请求、平台任务、实际部署版本、时间、结果及验证证据。不能把“提交了请求”写成“部署完成”。
- 原始配置、日志和证据保存在本地任务目录前应限定范围并脱敏；交付文档不放密码、令牌、Cookie 或完整敏感业务对象。
- 失败后先核实外部状态再重试，保留原失败记录；不要盲目重放部署、付款、迁移等外部副作用。

## 浏览器与 E2E

采用当前 agent 主机提供且用户允许的浏览器能力；存在明确浏览器偏好时遵守。无浏览器控制工具时提供测试清单和人工验证入口，不声称已完成自动 E2E。

验证实际入口、适用角色、正常与异常路径、键盘焦点、响应式，以及变更涉及的权限、异步和数据边界。登录所需密码、验证码、扫码确认和安全密钥由用户处理，不从浏览器或磁盘提取。

将用例、前置条件、步骤、预期、实际、版本、环境、执行时间和证据写入 Phase；失败及后续回归分开记录。

## 日志与观测

使用项目现有且获授权的日志/指标/追踪平台，按服务、版本、时间范围和关联 ID 查询。没有权限或数据时说明缺口，不能把无数据当作无故障。

## 修复与完成

修复回到当前任务分支，完成本地验证后生成新候选，沿已确认部署流程执行，重跑原失败和相关回归。状态、实际 SHA、文档与证据一致后再尝试完成门禁。手动归档可在任何阶段执行，归档不会使未完成项或失败测试变成完成。
