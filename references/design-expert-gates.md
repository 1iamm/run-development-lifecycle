# UI 设计与评审

在 Phase 中记录 UI 是否适用以及设计依据。纯后端、数据或配置任务记录有依据的 N/A，不要求原型或设计专家工具。

沿用已有组件且无设计分歧时，记录组件、Token、响应式和可访问性约束即可。存在真实交互取舍时，准备必要的对比原型，让用户选择后再实现。不要为简单改动强制生成多个方案。

原型置于任务的 `deliverables/` 或 `evidence/`，与业务实现分开。记录页面入口、布局、正常/空/加载/失败/禁用/权限状态、返回路径、键盘焦点和适用的触控行为。

如当前 agent 已具备设计、动效或原型专用能力，可按其实际适用性使用；这些能力是可选辅助，未安装不阻塞核心工作流，也不自动安装或冒充已运行。设计评审不替代真实功能测试。

只有动效有明确用途时才使用，记录触发、时长、打断和 Reduced Motion 行为；无新增动效无需额外动效评审。实现沿用项目组件和样式，测试真实交互与响应式。

主生命周期负责状态、批准、Git、规格、依赖、构建、发布、验证与完成判定；设计辅助工具不能自行扩大这些权限。
