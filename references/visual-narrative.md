# 图表优先与“总—分—总”叙事

为 PRD、技术方案及其每个目录/模块使用同一叙事顺序。目的是让读者先知道要解决什么，再看证据和设计，最后知道结论、验收与下一步。

## 整体结构

1. **总：先给结论。** 用 2–4 句说明问题、目标、范围和推荐方案；复杂项目配一张总览图，让读者定位各模块。
2. **分：逐模块展开。** 按用户路径、系统边界或业务能力拆分，每个模块使用下面的小结构。图说明关系和行为，表列出精确信息。
3. **总：收束决策。** 用表汇总需求/方案到验收的对应关系、主要风险、待确认事项、里程碑与下一步。结尾不重复全文。

## 每个目录或模块

| 层次 | 应回答的问题 | 推荐形式 |
| --- | --- | --- |
| 模块结论 | 本模块负责什么，解决什么问题，方案是什么 | 简短结论 + 输入/输出/边界表 |
| 设计展开 | 如何运作、与谁交互、有哪些分支和约束 | 流程/时序/状态/ER 图 + 需求/接口/字段/规则表 |
| 模块收束 | 决策是什么，影响谁，如何验收，剩什么风险 | 决策/验收/影响/待办表 |

不要直接堆图或列字段。每张图前用一句话指出要说明的结论，图后标出关键分支、约束或需要确认的点。术语和 REQ/API/TC 编号保持跨图表一致。

## 图表选择

| 要说明的内容 | 优先形式 |
| --- | --- |
| 用户从入口到完成、含异常和返回 | Mermaid flowchart 或 SVG 流程图 |
| 多端/服务调用、事务与异步边界 | Mermaid sequenceDiagram 或 PlantUML 时序图 |
| 状态与合法迁移、重试、终态 | Mermaid stateDiagram 或 PlantUML 状态图 |
| 表、键、关系、基数与逻辑关联 | Mermaid erDiagram 或 PlantUML/SVG ER 图 |
| 应用分层、依赖、模块边界 | 架构图/组件图 |
| 优先级、规则、字段、接口、用例、资源、排期 | HTML 表格 |
| 单个结论或简单约束 | 一两句话，不为凑图表增加复杂度 |

PRD 至少在需要解释路径/状态时提供对应图，并用需求与验收表说明精确行为。技术方案按实际适用性选择架构、时序、状态和 ER 图；没有数据变更不强画 ER，简单任务不强制所有图种。

## 图源与 HTML 交付

- 优先保留可编辑 `.mmd`、`.puml` 或 `.svg` 源文件，放在任务 `deliverables/` 或 `evidence/` 内；引用来源和版本。
- Mermaid/PlantUML 用当前环境已具备且允许的工具渲染为 SVG/PNG，再嵌入独立 HTML；也可生成自包含 HTML/SVG 图。需要新依赖时按主机和项目约定处理，不擅自向公网渲染服务发送内部方案。
- HTML 必须能直接看到图。不要用未渲染的代码块或外链占位声称已交付图。源码可放 `<details>`，渲染结果优先展示。
- 核心运行时不带 Mermaid/PlantUML 引擎。`workspace document` 生成结构化标准页；图示丰富的 PRD/技术方案由 agent 按本规范生成完整自包含 HTML，再用 `workspace deliverable` 登记对应种类。保持元数据、事实、版本和台账一致。
- 图表必须有标题、必要图例、清晰箭头/关系、适当替代说明；不要只靠颜色表示新增/修改/删除。大图允许局部缩放/横向滚动，不能把正文一起撑出屏幕。
- 生成后在实际浏览器中检查布局、字体、箭头、表格溢出和离线依赖；未核验的部分应准确说明。

## 结构化内容写法

现有 artifact 的 `summary` 记录模块结论，`details` 记录图表的结构/源路径和精确规则；可追加 `conclusion` 对象，记录决策、验收、影响、风险与下一步。不要复制已有需求、测试和发布状态作为另一份事实来源，使用 ID 引用。

PRD/技术方案的总体结论和收束可放 Phase 的 `documents.product` / `documents.technical`，例如：

```json
{
  "summary": "本期解决的问题、范围和选定方案。",
  "conclusion": {
    "decisions": [{"id": "DEC-01", "summary": "已确认的方案取舍", "evidence": ["实际确认记录"]}],
    "acceptanceRefs": ["REQ-01", "TC-01"],
    "risks": [],
    "nextActions": []
  }
}
```

上例只是格式示意；新任务没有实际确认时写待确认，不能照抄为已批准。
